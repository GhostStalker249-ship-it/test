# Полная инструкция для новичка: установка и запуск Backup Monitoring Center

Эта инструкция написана для человека, который **никогда не запускал приложения**.

---

## 1) Что вы получите

После выполнения шагов у вас откроется сайт с дашбордом мониторинга backup-систем.

В браузере это будет адрес:

- `http://localhost:3000` (если запускаете на своём компьютере)
- `http://IP_СЕРВЕРА:3000` (если запускаете на удалённом сервере)

---

## 2) Что нужно заранее

Вам нужен компьютер или сервер с:

1. **Linux / macOS / Windows**
2. Установленный **Docker Desktop** (для Windows/macOS) или **Docker Engine** (для Linux)
3. Интернет для скачивания Docker-образа `node:22-alpine`

> Если не знаете, установлен ли Docker — откройте терминал и выполните:
>
> ```bash
> docker --version
> ```
>
> Если видите версию (например, `Docker version ...`) — всё хорошо.

---

## 3) Самый простой способ (рекомендуется): запуск через Docker Compose

### Шаг 1. Откройте терминал

- **Windows**: PowerShell
- **macOS**: Terminal
- **Linux**: Terminal

### Шаг 2. Перейдите в папку проекта

```bash
cd /путь/к/папке/проекта
```

Пример (Linux):

```bash
cd /opt/backup-monitoring-center
```

### Шаг 3. Запустите приложение

```bash
docker compose up -d --build
```

Что делает эта команда:
- соберёт образ приложения;
- запустит контейнер в фоне;
- откроет порт `3000`.

### Шаг 4. Проверьте, что всё запущено

```bash
docker compose ps
```

Вы должны увидеть сервис `backup-monitor` в состоянии `Up`.

### Шаг 5. Откройте в браузере

- локально: `http://localhost:3000`
- на сервере: `http://IP_СЕРВЕРА:3000`

---

## 4) Как остановить приложение

```bash
docker compose down
```

---

## 5) Как перезапустить после изменений

Если вы поменяли файлы проекта, выполните:

```bash
docker compose up -d --build
```

---

## 6) Как смотреть логи (если что-то не работает)

```bash
docker logs -f backup-monitor
```

Чтобы выйти из просмотра логов: нажмите `Ctrl + C`.

---

## 7) Проверка API (техническая проверка)

Выполните команду:

```bash
curl http://127.0.0.1:3000/api/providers
```

Если всё хорошо, увидите JSON со списком систем:
- `cyber-backup`
- `ru-backup`
- `veeam`

---

## 8) Что делать, если не открывается сайт

### Проблема 1: Порт 3000 занят

Признаки: контейнер не стартует или падает.

Решение:
1. Откройте `docker-compose.yml`.
2. Замените строку
   - `"3000:3000"`
   на
   - `"3100:3000"`
3. Перезапустите:

```bash
docker compose down
docker compose up -d --build
```

Теперь сайт будет на `http://localhost:3100`.

### Проблема 2: На сервере не открыт порт

Если локально работает, а с другого компьютера нет:
- откройте порт `3000` в firewall/security group сервера.

### Проблема 3: Docker не найден

Если команда `docker` не работает:
- установите Docker Desktop / Docker Engine;
- перезапустите терминал;
- проверьте снова `docker --version`.

---

## 9) Настройка реальных источников (по желанию)

По умолчанию приложение использует demo-настройки. Для подключения реальных API систем backup настройте переменные окружения в `docker-compose.yml`:

- `CYBER_BACKUP_BASE_URL`
- `CYBER_BACKUP_TOKEN`
- `RU_BACKUP_BASE_URL`
- `RU_BACKUP_TOKEN`
- `VEEAM_BASE_URL`
- `VEEAM_TOKEN`

После изменения — перезапустите:

```bash
docker compose up -d --build
```
